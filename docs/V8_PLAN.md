# V8 实施计划：动效刻度、通用预设与可恢复运行

日期：2026-09-08

本版在现有 kxy.workflow.v1、LFX 单进程运行时和 SQLite 持久化之上做最小增量。产品代码只修改现有后端、前端组件和说明文档；父任务维护的 `acceptance/v8_supervisor_checks.py` 不在本计划中改写。

## 1. 动效刻度

- `motion_intensity` 继续作为持久化键，但 V8 默认值改为 30。
- 首次启动时用内部迁移标记记录是否已完成 V8 迁移：旧数据库中已有的 V7 值按 `old * 0.3` 转为新的整数刻度（四舍五入），没有旧值的新数据库直接保留默认 30。标记写入后重复启动不再换算。
- 前端 `DEFAULT_APPEARANCE` 及其发出的完整设置对象同步改为 30；若运行快照或旧导入 JSON 带有旧外观值，只作为历史记录保留，不在恢复时把它当作当前默认值重复换算。
- 前端把新的 0–100 刻度转换为连续系数：
  - 0–30：`scale / 30`；
  - 30–100：`1 + (scale - 30) * 2 / 70`。
  30 因而与 V7 的 100 完全一致，100 为旧完整效果的 3 倍系数。
- 0 在进入 RAF/高亮计算前短路；现有网格坐标读取、缩放/平移、节点避让、页面隐藏和 `prefers-reduced-motion` 逻辑保留。高亮数量仍设置上限。

## 2. 通用组件预设

- 新增 `component_presets` 表与 `/api/presets` 的列表、保存、删除接口，允许 `file`、`text`、`input`、`analyzer`、`container`、`condition`、`human`、`blackbox`；`subflow_input`、`subflow_output` 只能作为黑盒边界，不能独立保存。
- 现有 `/api/analyzers`、`analyzers` 表和前端分析器预设数据保持兼容。通用列表把旧分析器记录作为 `kind=analyzer` 的同一份记录呈现，不复制或覆盖；分析器保存仍走原 API。
- 预设保存只去掉节点身份、运行态和敏感字面量，保留 `file_id`、`skill_ids`、`model_ref`、`mcp_ids`、`grant_id` 等本机引用。应用时只引用已有本机资源，不自动创建文件授权；缺失/撤销的引用在界面中明确显示并拒绝静默替换。
- 组件库按组件类别分组，每组支持按最新日期或名称排序。展开详情、应用、删除互相独立；应用普通预设新建节点并走现有撤回历史，应用黑盒预设递归重映射节点和边 ID，只复制内部图和边界映射，不复制运行态、外部边、运行结果或凭据。
- 仅在现有检查器增加一个共用“保存为组件预设”入口；人工确认、黑盒编辑和全局设置页面的原有操作不重做。

## 3. 同 run 可恢复运行

### 持久化 checkpoint

- 新增 `run_attempts` 表，记录 `run_id`、递增尝试号、状态、开始/结束时间、失败原因、复用节点和重跑节点；`get_run` 暴露尝试审计。
- 创建新 run 时记录第 1 次尝试。每个成功节点的既有 `run_nodes.output` 作为 checkpoint；新增运行快照版本标记为 `kxy.run.checkpoint.v8`，旧运行没有该标记时恢复接口返回明确的“无 V8 checkpoint，不能恢复”。
- checkpoint 只恢复成功节点；失败、运行中断、未执行以及重新呈现的人工节点从头执行。条件节点保存完整的结果和所选 `true`/`false` 路由，恢复时重新调用条件输出的 stop/exclude 语义，不能把两个分支都放行。
- blackbox 继续使用已编译的扁平图；外层卡片状态由内部节点镜像。黑盒内成功节点逐个复用，失败内部节点从头跑，不把黑盒当成一个不可分割的“成功”结果。

### 恢复 API 与安全边界

- `POST /api/runs/{run_id}/resume` 不接受当前画布作为输入，只读取数据库中的原始运行快照、输入副本、Skill/MCP 快照和已解析模型绑定。
- 仅 `failed`、`interrupted` 可恢复；成功、取消、人工拒绝、正在运行或等待中的 run 返回 409。已有审批为 `interrupted` 且没有 decision 时，恢复前回到 `pending`，继续展示同一份确认内容；`rejected`、未确认或其他终态不会转成通过。
- 恢复前检查所有成功 checkpoint 的输出路径都在该 run workspace 内，并验证文件类型、存在性、大小和哈希；检查快照中的输出 grant 仍存在、未撤销、目录仍是原始真实目录。检查失败只记录拒绝原因，不执行 CLI。
- 恢复前也重新验证快照中的 `sources.file_path`/SHA-256 与 Skill 快照目录/hash；输入、Skill、模型选择均以原快照为准。
- 同一个 `run_id` 同时只允许一个 active attempt：进程内锁加 SQLite active-attempt 唯一约束，竞争恢复返回 409。恢复使用新的 node workspace，保留旧尝试以便审计；不声称能够续接 token stream。
- 容器导出使用带期望文件清单和 SHA-256 的完成 receipt。已存在且 receipt 完整一致的本 run 输出直接复用；半成品、无 receipt 或内容不一致时不覆盖旧目录，安全停止并报告原因。成功授权复制只产生真实已完成的输出记录。
- 服务重启只把 pending/running/waiting 标为 interrupted，保留已经 succeeded 的 `run_nodes` 和结果。恢复线程只在当前 attempt 仍有效时更新最终状态，禁止旧线程覆盖新的审计状态。

## 4. 验证顺序

1. 隔离 SQLite：默认/迁移幂等、0/30/100 刻度、边界校验、预设兼容和引用缺失检查。
2. 隔离 LFX：成功上游不重复执行、失败节点重跑、条件路由、黑盒内部节点、人工审批恢复、授权撤销和导出 receipt。
3. 前端独立浏览器：刻度迁移与持久化、八类预设的分组/日期名称排序/展开/删除、长名称、黑盒递归应用、恢复按钮和重启中断提示。
4. 仅构建 `frontend/dist-v8`；不覆盖正式 `frontend/dist` 或历史 `dist-v7`，不调用真实模型推理，不把测试凭据写入正式数据。

## 5. 明确不做

- 不增加新的 Manager/Service/Factory/Adapter 层。
- 不把 `subflow_input/output` 作为用户预设显示。
- 不自动重试失败运行、不绕过人工确认、不复制用户 Keychain 内容、不扩大文件授权、不改变人工确认设置界面。
- 不把 fixture、源码检查、LFX 成功或 CLI 进程退出当作真实模型语义、生产部署或现场运行证明。
