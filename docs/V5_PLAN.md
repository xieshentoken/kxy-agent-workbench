# V5 登录态模型选择与分析器绑定

2026-09-08。用户已要求规划后委托实现及验收；这是既有模型配置路径的定向改进，直接复用 React 状态、Agent discovery、agent_models 及 model_ref，不新增抽象层或依赖。

## 当前问题与目标

`frontend/src/v2.tsx` 的 manual 来源仍以输入框填写模型与 effort；`App.tsx` 的 Inspector 切换 Agent 会清空 model_ref，模型标签仅显示 alias/source。后端已有按模型返回的 efforts/default_effort 及确定性运行绑定，应复用并收紧界面与保存契约。

1. 将界面“手动”改为“登录态（本机 CLI）”。存储可保留 manual 兼容历史数据；原生发现目录与用户保存的分析器配置应可区分。登录态新建项不绑定 API credential；历史手动凭据记录不能被静默清除或当作纯登录态。
2. 打开模型页/切换 Agent 自动发现，并提供刷新。模型下拉仅取当前 Agent 的原生目录，不混入已保存 API/手动条目；使用真实模型 ID。标明读取来源/刷新状态。异步旧响应不能覆盖新 Agent 的草稿。无目录时显示原因和重试，不假造可选项。
3. effort 下拉仅列出当前模型声明支持的等级；切换模型立即更新选项及默认值，不残留其他模型的 effort。能力未知时标为 CLI 默认/未声明。API 模式仍允许用户填写服务真实模型 ID 和已知能力，保留连接测试。
4. 创建模型保存 Agent、alias、实际模型 ID、选中的默认 effort 与独立记录 ID。用户可为同一模型创建不同 alias/effort 配置。登录态保存应由后端核验所选原生模型与 effort，不信任客户端编造的能力，且刷新目录不能覆盖用户保存的配置。
5. Inspector 的 Agent/分析器下拉提供已配置的组合项（Agent · alias · 模型 · effort），选择时原子写入 cli/model_ref/effort 并清除旧模型/凭据覆盖。保留 CLI 默认入口和历史绑定；存在多个配置时不得任意挑选。模型记录显示 alias + 真正模型名；effort 显示确切值，未声明才显示 CLI 默认。节点仍可在当前模型支持范围内调整 effort，但不改写全局记录。
6. 存储、刷新页面、工作流保存/载入与既有预设均保持明确绑定；已删除模型不静默回退到其他模型。旧 API、native、manual 数据继续可读，既有登录态与全局 CLI 文件不改写。
