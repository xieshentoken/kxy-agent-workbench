## Shared API and data contract

Agent IDs: codex, claude, opencode, pi, hermes, workbuddy, deepseek. Labels: Codex, Claude Code, OpenCode, pi, Hermes, WorkBuddy, DeepSeek Harness. Profiles live globally in SQLite, not workflow nodes. A profile has id, label, executable, skill_roots[], available, version, status, message, models[], discovered_at. All seven appear even when unavailable. GET /api/agents returns profiles without synchronous expensive probing. PUT /api/agents/{id} saves executable/skill_roots (no shell command strings). POST /api/agents/{id}/discover explicitly refreshes version/models/efforts. GET /api/agents/{id}/skills scans only selected roots; POST /api/agents/{id}/skills/import accepts {paths: [discovered SKILL.md parent paths]} and returns {imported: [...], errors: [...]} after revalidation. Skills may have nested categories and symlinked root entries; resolve an explicitly selected entry, reject loops and unsafe descendant links, preserve original sources and limits.

Model record: {id, cli_id, model, alias, source: 'native'|'api'|'manual', efforts: string[], default_effort, discovery_source, credential_id?}. IDs are stable and distinguish native/API entries with identical model strings. UI displays alias plus source. GET /api/agent-models lists records; POST /api/agent-models creates a configured model; PUT /api/agent-models/{id} edits alias/model/efforts/binding; DELETE deletes. API credentials use existing /api/credentials/store and Keychain, are configured only in global UI; model stores opaque credential_id. Existing credential records remain usable. No guessed model/effort list presented as discovered; unavailable discovery returns a useful reason and allows explicitly labeled manual entries. Discovery list is not a guarantee of billing/login access. Filter hidden/internal-only model entries.

Analyzer stores cli + model_ref + effort (legacy model/credential_id remain readable). Resolve model_ref at run creation into immutable model/alias/source/credential reference/executable metadata; same resolution must work for analyzers inside blackboxes. Do not resolve anew after a human pause. Respect KXY_*_BIN test overrides. Removing a global entry must yield actionable rebind errors, not fallback to an unrelated model. Keys never in JSON snapshots/logs/responses/artifacts. Validate selected effort against known record. Runtime must use chosen executable/model/credential, with existing native/OS write confinement. Add verified headless command paths for installed CLIs; unsupported/missing protocol must be explicitly unavailable, never shell eval or invented argument mappings. No global auth/config mutation; no permission bypass flags. Network-off fails if not enforceable.

POST /api/picker accepts {kind: 'file'|'folder'} and returns {cancelled: bool, path?: string}. Fixed macOS native chooser script, argv array, no interpolated script paths; bounded timeout, clean cancellation, serialize concurrent dialogs. Frontend uses it for executable, skill folder, output folder. Existing browser file uploads remain native file selection; add folder upload where appropriate. No absolute-path window.prompt UI. Picker itself does not grant export permission; existing grants API does so after explicit user selection.

## Human and blackbox contract

Keep kxy.workflow.v1 backwards compatible. New node types human and blackbox. Human data: label, content (plain text/Markdown shown safely), confirm_label (default 确认继续). Standard items input and result output. Human shows active upstream preview and content; creates durable pending approval row and run status waiting. POST /api/runs/{run_id}/approvals/{node_id} with {decision: 'approve'|'reject', note?: string}. Approve passes original upstream data plus decision metadata; reject stops the run with rejected status; cancel wakes wait. get_run payload adds approvals[] with node_id, status, content, inputs, decision/note and timestamps. Duplicate/stale decisions return conflict. No approval implied by elapsed time, refresh or loading a flow. Skipped condition branches do not request approval. Preserve existing restart rule: unfinished runs including waiting become interrupted; no automatic replay of already executed agents. Clearly document this boundary. Existing in-process pause survives page refresh and may last indefinitely until decision/cancel. LFX must continue to control graph scheduling.

Blackbox data: {label, workflow: {version:'kxy.workflow.v1', nodes, edges}}. Interior has exactly one subflow_input and one subflow_output marker. Both use items/result ports; markers are passthrough collectors, not file sources or exporting containers. Compile nested graph into LFX's flat graph with collision-free bounded names and original path metadata; avoid a second scheduler. UI can add default pass-through blackbox, enter its canvas with breadcrumb, edit/save back, and pack selected connected nodes into blackbox/unpack it. First version supports one input and output: only lossless selections with one distinct incoming target and one distinct outgoing result source can be packed; explain otherwise. Preserve positions, edges, handles and existing condition routing. Recursively validate boundaries, cycles, malformed data, depth <= 4 and total expanded size <= 200 nodes/1000 edges. Internal file/text sources are permitted and must reach the output. During compilation, add hidden gate dependencies from box entry to internal source components so inactive outer branches cannot run them; visible file nodes still have no input handle. A root box without external input can seed an active empty entry for its internal sources. All input/skill/grant/model snapshots recurse and exports strip secrets and grants recursively. Internal human approvals must be visible/operable at top-level run panel. Surface inner failure and execution status on outer card. No cosmetic-only grouping.
