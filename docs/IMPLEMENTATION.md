# kxy MVP implementation contract

Approved 2026-09-05. Independent local application under ./kxy. User delegates code implementation to a new GPT-5.6 Luna max session; parent task owns architecture and acceptance. No changes to WhatFa or external Langflow/CLI source/configuration.

## Architecture decision

- React + TypeScript + Vite + XYFlow + Zustand frontend; FastAPI local backend. Reuse Langflow's actual LFX Graph runtime (pinned 1.12.0), not a fake renamed hand-written DAG scheduler. Reuse its architecture and XYFlow canvas idioms while adapting the shell and node cards to the supplied screenshot. A full copy of unrelated Langflow providers, account UI and integrations is unnecessary. Document this precise reuse boundary and retain any required upstream license notices.
- Own compact versioned workflow JSON (nodes, edges, settings), SQLite for workflows/configuration/run metadata, ordinary files for immutable inputs and versioned artifacts. Local-only single user. No Redis, PostgreSQL, hosted service, unrelated engine integrations or generic abstraction layers.
- CLI executables are black-box child processes. Codex and OpenCode are supported first; Claude/pi may be detected and marked upcoming. Runtime start, cancel, progress, failure and artifacts must be real. Never use a synthetic analyzer as the default or silently substitute demo output when CLI fails.
- Prefer a small number of cohesive files. An explicit function per CLI is appropriate. The LFX dependency must install via the kxy setup command; no permanent dependency on /Users/.../Projects/langflow or its .venv.
- Bind to 127.0.0.1, preferably port 8710. Serve built frontend from the backend for a one-command launch. Dev frontend may use 5178 with a local proxy. Protect state-changing local APIs from cross-origin requests; no permissive wildcard CORS with credentials.

## Visual and interaction contract

Reference: docs/reference.png. Adapt its warm, airy editorial character to an actual working canvas, not a marketing landing page. Warm paper #faf8f5, white surfaces, near-black text, muted sage #dce5da / mist blue #dce6f0 / pale apricot #f1e3d3 / soft lilac #e5dfec. Flat rounded rectangular node cards, approximately 20px radius, hairline border and very light shadow. A floating compact top bar, left component/skill library, central dotted infinite canvas, right inspector, collapsible bottom execution/results panel. Spacious but practical at 1440x900; inspectors must not obscure all canvas at 1280x720. Narrow screens get collapsible panels.

Chinese primary interface. Restrained kxy wordmark, no borrowed brand logo, no emoji icons. Lucide icons are fine. Typography defaults to local system sans for controls/body with a local serif heading option. No external font/network dependency. 8px spacing rhythm, 150ms feedback, prefers-reduced-motion support.

Appearance settings must actually update and persist: choose three palettes (paper/sage/mist), custom accent and canvas background colors, font presets (system sans, serif, monospace) plus safe local font-family custom input if simple. Maintain readable text contrast. Reset defaults. Apply typography to node cards and inspectors as well as the shell.

## Features and contracts

1. Canvas: add, select, move, delete nodes; connect and delete edges; pan/zoom/fit; save/load workflows; JSON import/export (no secrets/local credentials); three complete editable starter templates for extraction, expansion research, and cross-check. No auto-run on import/template select.
2. Files: dropping files on the canvas creates positioned attachment nodes. Also accessible upload button. Content-addressed immutable original files with SHA256 and safe display names. Support text/markdown, native-text PDF, JPEG/PNG and CSV/XLSX. Text/PDF/table extraction must retain page/sheet/row references and report truncation/empty/scanned/unreadable states. Images retained and passed as files to capable CLI paths. Other extensions can be retained as unsupported/pending, never marked parsed. Size limits and safe file paths. Results/input previews and download/open links.
3. Skills: import a local skill directory through backend native directory chooser or an explicit directory path, or a safe zip upload; preserve SKILL.md/scripts/references/assets. Reject path traversal, symlinks escaping roots and unreasonable size. Do not execute import code. Extract name/description, snapshot hash and compatibility/dependency text, show details. Allow attaching/removing skill badges on analyzers (MVP at least one); deterministic explicit mounting/loading in isolated node workspace. Do not rewrite global skills folders or pretend every host-specific skill is portable.
4. Analyzer: prompt textarea, CLI, available/explicit model, supported effort/variant, timeout, network choice, optional structured JSON output expectation. Settings must actually map to CLI arguments/environment. Credentials: existing CLI login by default; optional API key and compatible endpoint in settings using macOS Keychain or a fail-closed credential store with references only (never plaintext persistence). Do not inspect or show stored keys. A credentials status can state configured/not configured without reading values into API responses. UI should explain which backend/model is used.
5. CLI execution: isolated per-run/per-node workspace, immutable input copies, selected skill snapshots, input manifest and expected output folder. Use argv arrays, never interpolate prompts or paths into shell strings. Stream bounded redacted events, extract real final output and declared/generated artifacts, capture exit status, enforce timeout and cancel whole process group. Disallow unsafe global permission bypass. File write confinement must be enforced by actual CLI/OS controls, not a prompt-only promise. At minimum OpenCode external writes require an OS sandbox or equivalent enforcement, including shell child processes. Network off must be technically enforced or rejected as unsupported; cannot silently ignore it. Missing CLI/login/model/permission yields visible actionable failure, not green success. Codex supports exec --json --output-last-message and workspace sandbox; OpenCode run supports --format json, --file, --model, --variant. Validate actual local versions with --help.
6. Custom analyzers: save named presets with prompt/CLI/model/effort/skill snapshot references/output preferences; reuse from library and delete. No credentials embedded. Flow export/import must report missing local skills/credentials/assets and let user bind them; preserve available assets by ID when reimporting on the same machine.
7. Container: collect text/JSON/file artifacts, preview output and provenance (input hashes, workflow snapshot, prompt, CLI version/model/effort, skill hashes, timestamps). Can pass references to another analyzer. Choose authorized output folder (native chooser preferred; explicit path approval acceptable in local UI), persist grant, revoke. Write atomically to a unique per-run directory with an output manifest; never overwrite originals or existing outputs. Runtime verifies canonical path and symlink boundaries; export/import must not grant filesystem access by itself. Escape active content previews; no unsandboxed arbitrary HTML rendering.
8. Condition: field + operator + expected value form for structured upstream output (equals, contains, numeric compare, exists). True/false edges; invalid/missing required data must yield a distinct actionable error, not silently route false. Semantic evaluation belongs in preceding analyzer prompt. Reject cycles/dangling edges/invalid handles before run. Correct fan-in and skipped branches; a container after a branch receives only active results.
9. Runs: saved workflow/input/settings/skill snapshot per run; visible pending/running/succeeded/failed/skipped/cancelled states, log and final artifact preview. Cancel supported. Refresh preserves run display and artifacts. Server restart marks unfinished runs interrupted. Do not claim CLI stream or process success means output semantics are validated. No unattended private outreach or other external message sending.

## Acceptance

- Backend tests for graph validation, true/false and merge behavior, missing-condition-field errors, LFX execution, source preservation, skill import traversal, output grant revocation/path containment, immutable run snapshots, credentials redaction, actual argv mapping, nonzero/timeout/cancel subprocess behavior. Use labeled local CLI fixtures for fault cases; document which tests are synthetic.
- Frontend TypeScript + production build. Browser acceptance at 1440x900 and 1280x720, narrow-screen smoke, no actionable console errors, actual file drop -> nodes, connection/edit/save/reload, skill attachment/custom analyzer, both condition paths, output save, appearance persistence.
- Parent independently performs at least one real Codex and OpenCode smoke with only purpose-created public/synthetic material, if credentials and automatic approval allow it. No private files or stored secrets printed. Record exact limitations.
- Provide README with reproducible setup/start/test commands, architecture/reuse boundary, supported formats/CLI capabilities, credential/permission behavior. Parent will produce final acceptance report. Implementer must report completion and leave working launch processes if started, with PID/URL.

## Deferred

Legacy DOC/XLS/PPT, complex slide fidelity, scanned-PDF OCR pipeline, audio/video ASR, multiuser/cloud, skill marketplace, arbitrary code condition editor, unbounded loops, scheduled workflows, automatic CLI routing, deep WhatFa integration. Do not present retained unsupported files as fully analyzed.
